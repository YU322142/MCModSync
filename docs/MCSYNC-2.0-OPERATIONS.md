# MCSync 2.0 发布与运维

本文只描述当前 v5 工作流。旧 v1-v4 客户端升级见[旧版升级指南](中文使用指南.md)。

## 1. 发布前准备

发布输入必须是已经实际启动、进入测试服并完成关键玩法测试的客户端副本。不要直接拿下载缓存、服务端根目录或正在运行的实例发布。

发布前确认：

- Minecraft、加载器和 Java 版本正确。
- `mods/` 中不存在重复 Mod ID。
- MineAstr、沉浸画框等双端组件版本已经配对。
- 客户端没有正在运行的 Java 进程。
- 真实令牌、账户、世界、日志和地图缓存不在发布范围内。

## 2. 打开发布项目

运行：

```text
java -jar MCSync-2.0.0.jar
```

选择客户端的 Minecraft 根目录，而不是 `mods/` 子目录。发布项目保存编辑状态，不保存私有令牌。

## 3. Mods 页

Mods 页只处理 `mods/*.jar`。

每次扫描会计算当前文件哈希，并按以下顺序工作：

1. SHA-256 用于本地身份和旧 v5 精确对应。
2. SHA-512 查询 Modrinth 精确文件。
3. CurseForge fingerprint 只定位候选文件；导出时下载候选并复核大小与 SHA-256，失败则放弃该来源。
4. 两个平台均无精确结果时回退本地托管。
5. 自制或手工适配 Mod 可以保持本地托管。

`modId` 只用于升级后的描述与选项继承，不能直接继承旧下载地址。重新匹配不会覆盖已经填写的中文描述；英文为空时才可补入平台英文说明。

删除 Mod 后重新扫描或导入旧 v5，不会恢复已经删除的条目。

“扫描并识别升级”会以当前 `mods/` 为权威重建 Mods 表格：

- 当前与旧行路径一致时继承人工设置，并按当前文件重新匹配来源。
- 文件名和版本变化、但 modId 在新旧集合中都唯一时，视为替换升级；继承必须/推荐、双语描述、作用端、推荐平台限制和镜像偏好。
- 旧项目中 modId 本身不唯一时，不猜测继承来源，新文件按新增 Mod 处理。
- 当前 `mods/` 中同一 modId 出现多个 JAR 时，所有相关行显示“冲突”，不进行自动平台匹配，验证与导出保持阻断。
- 发布者必须删除旧版或重复 JAR，再重新扫描；GUI 不会擅自选择较新版本。

## 4. 同步范围

按用途选择范围：

| 范围 | 建议策略 |
| --- | --- |
| `mods/` | managed |
| `resourcepacks/` | managed 或 optional |
| `shaderpacks/` | managed 或 optional |
| `kubejs/` | managed |
| `tacz/` | managed |
| `tlm_custom_pack/` | managed |
| `config/` | additive + 精确配置项 OTA |
| `defaultconfigs/` | additive |
| `configureddefaults/` | first-install |
| `options.txt` | first-install |

“managed”允许移除上一发布版拥有、但新清单删除的文件；不会删除没有所有权记录的玩家文件。

发布器的“扫描安全内容目录”会扫描上述三个配置树以及其他已声明范围，不再依赖目录白名单。配置树中的账号/会话、凭据文件、备份、临时文件、解包缓存和包含 token/password/secret/API key 等敏感键的文档会被黑名单跳过；界面会列出路径和原因。黑名单只决定整文件能否进入发布清单，不替代配置键级 OTA。

配置自动分流规则：`defaultconfigs/**` 使用 additive，`configureddefaults/**` 使用 first-install；`config/**` 中明确的客户端画面、声音、按键与 UI 文件建立精确文件级 first-install 范围；同时包含玩法键和个人键的文件不进入整文件列表，并提示建立键级 OTA。FancyMenu 的布局、素材和主题读取 `config/fancymenu/{customization,assets,ui_themes}` 等发布路径；`fancymenu_data/**` 的上次世界、Buddy 进度、浏览器设置与临时网页属于玩家/运行态数据。

## 5. 配置 OTA

优先修改单个配置项，不要发布整个玩家配置目录。

每条操作应包含：

- 文件相对路径
- TOML/JSON/properties 类型
- 配置键路径
- 期望前像或允许值
- 目标值
- 是否要求重启

当前值不符合允许前像时操作失败闭锁，不猜测覆盖。世界 gamerule、玩家选项和存档数据不属于配置 OTA。

## 6. 可选内容

推荐 Mod、资源包和光影包会在首次出现或集合新增时显示选择界面，默认全选。玩家选择写入本地状态；仅描述或哈希变化不会反复弹窗。

必须内容不能取消。取消推荐内容不会削弱必须内容的严格校验。

## 7. 服务器列表

启用服务器列表同步时，发布器导出 `serverlist.txt` 和 `servers.dat`。客户端使用所有权台账只更新 MCSync 添加的条目，保留玩家自行添加或修改的服务器。

不要在公开测试仓库中提交真实私服地址；正式发布产物与公开源码是两套边界。

## 8. 验证与导出

导出前至少检查：

- schema 为 5
- releaseSequence 为当前发布序号
- minimumMCSyncVersion 合理
- 每个文件路径唯一
- 每个文件大小和 SHA-256 已锁定
- Mod 上游来源是精确哈希结果
- 非 Mod 文件没有模组站来源
- 配置操作有前像保护
- 管理范围没有存档和隐私目录

## 9. 上传顺序

首次全量发布时不要选择上一版基线。后续 OTA 才选择上一版**完整发布输出目录**或完整 v5 清单；平台验证证据与已有 SHA-256 对象可以复用，但稳定清单始终描述完整终态。发布器会生成：

- `UPLOAD-PLAN.json`：机器可读的上传、复用、外部来源和移除路径清单。
- `UPLOAD-GUIDE.zh-CN.md`：中文操作指南。
- `UPLOAD-GUIDE.en.md`：与中文内容完全等价的英文操作指南。

1. 首次全量发布上传 `objects/sha256/` 下的全部对象；后续只上传指南中尚不存在的新哈希对象。
2. 验证公网下载的大小与 SHA-256。
3. 上传 `manifests/<releaseId>.json` 完整历史清单和服务器列表等辅助文件。
4. 不覆盖任何已有哈希对象；只有确认所有保留清单均不再引用时才可清理。
5. 最后原子替换 `channel/stable/mods-v5.json`。
6. CDN 存在缓存时确认稳定清单已生效。

不要先发布引用尚未上传文件的新清单。

## 10. 回滚

正常回滚应发布一个**更高 releaseSequence** 的修复清单，内容指向经过验证的旧文件。不要把云端序号调小；客户端会把它识别为降级攻击。

客户端本地事务失败时会使用备份和日志回滚。不要在游戏运行期间手动改写 `.modsync/` 状态。

## 11. 验收

至少测试：

- 全新客户端首次安装
- 旧 v5 客户端增量升级
- 推荐内容选择与取消
- Mod 改名但哈希相同
- Mod 升级后通过唯一 modId 继承描述并重新匹配
- 同一 modId 同时存在两个版本时显示冲突并阻止导出
- 删除 Mod 后不被旧清单复活
- 镜像返回错误文件时回退官方来源
- 断网、下载截断和哈希错误时阻止启动
- 更新完成后重启进入游戏
