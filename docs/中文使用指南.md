# MCSync 旧版升级兼容指南

本文只用于把已经安装的 MCModSync 1.6.x、1.7 或 1.9.x 客户端迁移到 MCSync 2.0。新频道不要从 v4 开始，请直接使用 `mods-v5.json` 和[当前发布流程](MCSYNC-2.0-OPERATIONS.md)。

## 为什么旧入口仍然存在

旧客户端只认识发布时写死的 URL、`mods.txt` 或 `mods-v4.txt`。MCSync 2.0 无法让尚未升级的旧 JAR 凭空读取新地址，所以原地址必须暂时保留升级材料。

技术兼容名称也必须保留：

- Mod ID `mcmodsync`
- `modsync.properties`
- `.modsync/`
- `MCModSync-Config.jar`

仓库和产品可以叫 MCSync，兼容标识不能直接删除。

## 升级材料

旧地址只需要提供能把客户端带到 2.0 的最小材料：

```text
legacy-channel/
├─ mods.txt
├─ MCSync-2.0.0.jar
└─ MCModSync-Config.jar
```

实际文件名和清单格式必须符合对应旧版本的读取能力。不要把完整新整合包继续维护在旧地址。

配置引导应把新 `manifest` 写向独立的 v5 地址：

```properties
manifest=https://files.example.com/minecraft/channel/stable/mods-v5.json
strict=true
requireManifest=true
```

## 玩家侧过程

根据旧版本能力，通常需要两到三次启动：

1. 旧同步器读取原地址并安装 MCSync 2.0 与配置引导。
2. 玩家重新启动。
3. MCSync 2.0 读取新 `mods-v5.json`，完成正式内容迁移。
4. 如有 JAR 变化，再重新启动一次进入游戏。

这是启动前替换 JAR 的安全限制，不是下载失败。

## 发布顺序

1. 先发布并验证新 v5 频道。
2. 确认 MCSync 2.0 JAR 和配置引导可下载。
3. 最后更新每一个历史 URL 的升级清单。
4. 保留旧 URL，直到对应客户端已经完成迁移。
5. 旧入口不要重定向到错误 Minecraft 版本或加载器的频道。

## 禁止事项

- 不要在新 v5 目录旁复制一套 v4 作为“兼容”。
- 不要删除旧客户端仍会访问的历史 URL。
- 不要让 1.21.1 与 1.21.11 共用其他 Mod 清单。
- 不要通过降低 releaseSequence 回滚。
- 不要把令牌、私有服务器地址或玩家数据写进配置引导。
